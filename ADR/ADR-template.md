# ADR 模板

> 架构决策记录（Architecture Decision Record）。每次对内核边界 / API / 版本策略的
> 不可逆决策都记一条。轻量、追加式、不删改旧记录。

**文件名**：`ADR-XXXX-<简短主题>.md`（XXXX 从 0001 递增）

---

## ADR-XXXX · <主题>

- **状态**：提议 / 已采纳 / 已弃用
- **日期**：YYYY-MM-DD
- **决策人**：<名字 / agent>
- **背景**：为什么现在要做这个决定？（触发条件、约束、痛点）
- **决策**：我们决定 ______。
- **理由**：
  - 依据 1（可引用 Karpathy 准则编号 / 实测数据 / 项目铁律）
  - 依据 2
- **影响**：
  - 正向：______
  - 负向 / 代价：______
  - 受影响文件：`<path>`
- **备选方案**（被否决的）：
  - 方案 A：______（否决理由）
  - 方案 B：______（否决理由）
- **后续**：是否有 P2 / 待验证项？

---

## 示例（已采纳，2026-10-10）

### ADR-0001 · LADDER 作为注入参数而非内核常量

- **状态**：已采纳
- **日期**：2026-10-10
- **决策人**：Jason + agent（LESSON-OS 分支）
- **背景**：核对真实源码发现 bb-prep `LADDER=[1,2,4,7,14,28,45]`、
  vocab-app `LADDER=[1,2,4,7,15,30,60,120]` —— **并非逐字节相同**
  （早期对话误称「逐字节相同」，已勘误）。
- **决策**：`learn_engine.scheduler` 的 `next_schedule` / `apply_result` 一律接收
  `ladder` 参数，内核只提供 `DEFAULT_LADDER`（bb-prep 默认）。
- **理由**：R2 简洁 + 不把项目参数塞进共享内核；状态机逻辑同源，仅间隔长度因项目而异。
- **影响**：vocab-app 接入时传自己的 ladder；bb-prep 不传即用默认。无破坏性。
- **备选**：硬编码单一 LADDER —— 否决（会强制 vocab-app 改节奏，违背版本闸门）。
