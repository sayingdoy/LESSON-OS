# ADR-0004 · 归因闸门候选 JEV `noul`（状态：未测，暂不启用）

- **状态**：提议（**未测，不得启用**）
- **日期**：2026-10-10
- **决策人**：Jason + agent（LESSON-OS 分支）
- **背景**：飞轮的核心判定点是「这个缺陷会不会在其他项目重现」（归因）。
  这是**真判断题**，确定性代码做不了 —— 需要用 JEV `noul` 模型判定。
  但直接启用有**三个必须先解决的前置问题**。

- **决策**：
  1. **P1 期间不启用 JEV 归因闸门**。先用确定性规则（agent 判断 + 留标记）。
  2. 累计 **≥16–20 条归因记录**后，才做预登记 + 重测阈值。届时另开 ADR 采纳/否决。
  3. **阈值必须重测，不可抄 `0.30` / `0.70`** —— 那对数字只对
     "内容在未来…仍然成立且有用吗"这一条问句有效；归因是**新问句**。
  4. **归因问句措辞必须固定**并写进 PLAYBOOK §10.4。
  5. **适用范围硬边界**：仅限个人学习项目；**排除一切工作数据**。

- **理由**：
  - JEV §3 实测：**同一句加个前缀，概率 0.660 → 0.42**（0.25 量级抖动）
    → 抖动不是问题，**用词**才是。故措辞必须固定；
  - JEV 参照集 n=16 → 样本不足，此刻测阈值无统计意义；
  - JEV 生产路由 **OpenRouter 是美国节点**：个人内容 ✅；
    **工作内容 ❌（德企数据出境）**，且本地 Laya 已判废对中文不可用
    → **工厂场景这条路目前是断的**；
  - JEV 明确**不做生成 / 计划 / 价值决策** → submodule vs vendor 选型、
    备份策略、MAJOR 授权**不该交给它**（那些是价值决策，见 ADR-0003）。

- **影响**：
  - 正向：避免在无数据支撑时贸然上模型；阈值一旦有据可依再上，风险可控；
  - 代价：P1 期间归因靠人工，稳定性仅"中" → **必须有阶段边界对账兜底**
    （PLAYBOOK §10.3）；
  - 受影响文件：`PLAYBOOK.md` §10.4/§10.5

- **备选方案**：
  - 方案 A：**P1 直接上 JEV 归因** —— 否决：阈值未测 + 样本不足，
    等于用未标定的闸改变结果，违反 JEV 自身铁律
    （"判不准的闸不能成为改变结果的那一环"）；
  - 方案 B：**完全放弃模型，纯人工归因** —— 否决：归因是真判断题，
    人工也能做但不可规模化、不可审计；保留为 P1 的**现状态**即可；
  - 方案 C：**本地模型替代（Laya）** —— 否决：已判废，对中文不可用。

- **迁移复用（非新增开发）**：JEV §8「改动一个已在跑的闸」纪律整体迁移到
  "改内核"流程 —— 预登记 / 点火验证 / 失败条款前置 / 部分通过就报部分通过。
  **这条零成本、立刻可用**，已落入 ADR-0002 与 `PLAYBOOK.md` §10.6。

- **后续**：累计 ≥16–20 条归因记录 → 另开 ADR 记录阈值重测结果。
