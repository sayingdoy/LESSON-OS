# ADR-0002 · golden-set 逐字节比对作为内核变更的验收法

- **状态**：已采纳
- **日期**：2026-10-10
- **决策人**：Jason + agent（LESSON-OS 分支）
- **背景**：P1 要从 bb-prep `src/` 把逻辑抽进 `learn_engine`，硬约束是
  **bb-prep 行为零中断**（每天要出卷）。但"行为不变"若无机械判据，
  只能靠人工目测 —— 而目测在 527 题规模上必然漏。
  同时，JEV §8 提供了已被 13 天线上数据检验过的**预登记纪律**，
  恰好补上"验收标准什么时候写死"这一环。

- **决策**：
  1. **golden-set 逐字节比对**：固定一批 items + 固定 `today` + **固定 `rng` 种子**，
     对改前 / 改后各跑一次出卷，**输出逐字节比对**；
  2. golden-set 放**内核内** `learn_engine/tests/`，用**纯 stdlib `unittest`**
     （不引 pytest，守住零外部依赖铁律）；
  3. **预登记**：通过门槛在看数据**前**写进独立 dated 文件，之后不许改；
  4. **点火验证**：改完必须跑一次**真实出卷**（不是只跑单测）；
  5. **失败条款前置**：「P1-A 不过 ⇒ 不进入 P1-B」；
  6. **部分通过就报部分通过**。

- **★ 验收第 0 步：固定随机源（2026-10-11 补，裁决 B3）**

  > **未固定 `rng` 时，逐字节比对不成立 —— 判据作废。**

  - 出卷链路含 `rng.shuffle` / `rng.random()` 排序键（bb-prep `practice.py`
    实测：`rng = random.Random(a.seed)`，CLI 暴露 `--seed`，help 明写「测试用」）。
  - `Random(None)` 用系统熵 → 同输入两次跑出不同卷面 → 比对必然失败，
    与代码改动无关 → **判据退化为噪音源**。
  - **固定种子值统一为 `20261010`**（写入本 ADR，执行者不得临场另选，
    否则不同人跑出不同基线、无法互认）。

  验收命令模板：
  ```
  rng = random.Random(20261010)      # 与 ADR 一致，勿改
  ref = dt.date(2026, ...)           # 固定 today
  items = <固化样本>                  # 固定 items
  ```

- **理由**：
  - 逐字节比对是**可机械化**的判据，命中 VCP 步骤 6 硬规则
    （"机械性违规一律做成确定性检查"）；
  - `today` **与 `rng` 都必须固定**，否则日期/随机驱动的不确定性会污染比对
    （`today` 缺失是 2026-10-10 原始判据的疏漏，2026-10-11 补 `rng` 时一并固化）；
  - 预登记防"看完结果再定标准"（JEV 实测这套纪律线上 13 天有效）；
  - 放内核内而非各项目内：验收的是**内核**，测试应随内核走、随版本发布。

- **影响**：
  - 正向：P1 每次改动都有**确定性回归网**；MAJOR bump 前必须过 golden-set；
  - 代价：需先建 `tests/` 骨架并固化一批样本（P1-A1 工单）；
  - 受影响文件：`learn_engine/tests/`（新建）、`PLAYBOOK.md` §10.6、`AGENTS.md` §5

- **备选方案**：
  - 方案 A：**只跑单测，不做逐字节比对** —— 否决：单测覆盖不到出卷的
    组合行为（九域权重 + 去重窗口交互），"测试全绿但输出变了"是真风险；
  - 方案 B：**golden-set 放各消费项目内** —— 否决：会复制 3 份，
    违背单一真源，且内核升级时三处漂移；
  - 方案 C：**引入 pytest + 快照库** —— 否决：破坏"零外部依赖"铁律，
    而 stdlib `unittest` 完全够用。

- **后续**：P1-A1 建立骨架；阈值类（JEV 归因闸门）若启用，
  其预登记流程复用本 ADR 的纪律（但阈值须另测，见 ADR-0004）。
