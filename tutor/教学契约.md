# tutor · 教学契约（共用闭环）

> **tutor-prompt-library 种子文档** · 版本 0.1.0 · 2026-10-13 · Owner: Jason
>
> 本文件是 LESSON-OS 三层资产中**「提示 / 审美库」层的第一个实体**——
> 承载「学习 → 间隔复习 → 考试 → 错题复盘」闭环中**判断性与审美性**的共识
> （怎么教、怎么反馈、怎么总结）。确定性逻辑不在这里（那在 `learn_engine`），
> 项目专属形态也不在这里（那在各消费方）。

---

## 1. 定位与边界

| 层 | 载体 | 管什么 |
|---|---|---|
| 代码内核 | `learn_engine/` | 确定性逻辑：调度、判分、到期判定（模型不参与） |
| **提示 / 审美库** | **`tutor/`（本目录）** | **判断与审美：教学契约、讲评风、复盘格式** |
| 约定手册 | `PLAYBOOK.md` | schema、API 契约、触发协议、差异清单 |

**入库判据（防过早抽象，Karpathy 准则 2）**：一条约定只有同时满足
① 在 **≥2 个消费项目**中真实存在（同形或同构，有文件可指证）；
② 剥离领域细节后**内核确实相同**；③ 有背景的人不看记录会困惑「为什么不统一」——
才升级为本库资产。**不为未来的可能性提前建资产。**

## 2. 错题复盘约定（本库第一条契约，v0.1.0）

**闭环**（2026-10-10 对三项目真实工作流核对，原载 PLAYBOOK §7，2026-10-13 迁入此处）：

```
录入 → 分析（归纳同类错误共性）→ 出题验证（AI 出同类题，答对才算"已复习"）→ 已复习
```

- 参考实现：AI-Kongzi `modules/错题整理系统/`（已建此闭环）；
  bb-prep `04-复盘/` 同构；vocab-app 的成绩单 + 错词行是同构的轻量形态。
- **判定权归确定性代码或显式人工确认，模型不直接判分**（对齐判分铁律，
  PLAYBOOK §5）：AI 只做归纳、出题、讲解等判断性工作。
- **复盘产物必须可复现**：同一份作答数据，重复生成复盘不改变判定结论。

## 3. 使用规则（引用或拷贝，**不做常驻技能**）

- 消费方两种合法用法：**引用**（文档中链接本文件）或**拷贝**
  （复制为项目内资产，如 vocab-app `src/prompts/ljg-word.md` 的先例）。
- 🔴 **不注册成常驻 skill**。两条实测教训（2026-09-11，vocab-app AGENTS.md §六
  有全文）：① 常驻 skill 每回合烧 token；② 共享技能库的 SKILL.md 会被外部工具
  写字段污染。拷成项目资产 = 零常驻成本、零污染、可随时改。
- 拷贝时**在文件头注明来源与本文件版本**（溯源），语义变更回哺本库。

## 4. 版本与变更

- 本库**独立于 `learn_engine` 版本化**（内核 semver 管代码，本库管约定）；
  契约的破坏性变更（改闭环步骤、改判定权归属）= MAJOR，须 Jason 确认。
- 变更记录写在各文件头（`版本 x.y.z · 日期`）；两条以上实体后建
  `tutor/CHANGELOG.md`。
- 与 PLAYBOOK 的关系：PLAYBOOK 只留**指针**（§7），内容以本文件为 SSOT，
  **不在两处复刻**（防双 SSOT，对齐 B7 纪律）。
