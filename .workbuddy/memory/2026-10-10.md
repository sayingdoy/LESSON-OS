## 触发协议设计（2026-10-10 讨论产出，待落 PLAYBOOK §10）
- 结论：飞轮**不能靠 agent 自觉触发**，必须机械化。三个入口：
  - A 新项目立项 → 立项清单强制问「是否消费 LESSON-OS？钉哪个版本？」
  - B 排优化工单 → 工单前置问句「这是共性还是特性？」
  - C 运行中发现 → **先修项目（不阻塞生产）+ 留一行沉淀候选标记**，归因推迟到阶段边界批处理
- 关键诚实边界：**「发现」这个动作无法机械检测（只能写 AGENTS.md 约束），「上报/留标记」可以机械化检查。**
- 三档成本：L1 微沉淀（留标记，~1 分）／L2 中沉淀（改内核+ADR，~30 分）／L3 大沉淀（+审计，~60 分）。
- 盈亏平衡：单次沉淀 ~45 分钟 vs 每项目重复排查 ~90 分钟 → **预计重现次数 ≥ 2 即正收益**。
- 风险：漏报（共性当特性→漂移）、滥报（特性当共性→内核缝合怪）、当场改内核（阻塞生产）、版本漂移、仪式过重。
  兜底：阶段边界强制对账 + 内核定期 audit。
- 归属：协议正文写 PLAYBOOK §10（SSOT），`AGENTS.md` 只放指针（遵守 AGENTS.md 一屏约束）。
