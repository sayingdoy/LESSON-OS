## B1 —— `judge` 契约：字符串 or bool

### 实测

| 位置 | 实测签名/返回 |
|---|---|
| `vocab-app/src/review.py:137` | `def judge(raw: str, word: str) -> str:` → `return "correct"` / `"wrong"` |
| `vocab-app/src/settle.py:154` | `"correct": R.judge(q["answer"], word) == "correct"` ← **调用方做字符串比较** |
| `bb-prep/src/bbcore.py:401` | `def judge(raw: str, item: dict) -> str:` → `return "correct"` / `"wrong"` |
| `LESSON-OS learn_engine/grader.py:14` | `def judge(self, raw: str, expected) -> bool:` ← **只有内核是 bool** |
| `PLAYBOOK.md:110` | `judge(raw, answer) -> "correct" \| "wrong"` ← SSOT 原本就写字符串 |

### 判断

**两个真源 100% 一致：都返回字符串，没有一个返回 bool。** 内核的 bool 是**孤例**——
四方里唯一不一致的一方就是内核自己。SSOT（PLAYBOOK）原本写的就是字符串，是内核实现跑偏了。

关键证据：`vocab-app/settle.py:154` 是 `== "correct"` 比较，而不是直接当布尔用。
说明字符串返回值是**有意设计**，不是历史遗留。

### 建议：**取字符串 `-> str`**

理由（按优先级）：

1. **对齐真源**（两个都不改）—— 内核是抽象层，应向实现收敛，不是反过来。
2. **省一次 MAJOR** —— 若内核取 bool，两个消费方接 adapter 时都要包一层转换，
   且未来若要区分 `"blank"`（空作答）与 `"wrong"`，bool 直接丢失信息。
   注意 bb-prep `judge_tf` 已有 `'blank'` 语义（docstring 明写），bool 无位可放。
3. **PLAYBOOK 不用改** —— SSOT 文本本来就对。

### 落地动作（建议顺序）

1. 改 `grader.py`：基类 + `ExactMatchGrader` 返回 `-> str`。
2. 更新 `grader.py:3` 的模块 docstring（顺带修 B5 的铁律引用）。
3. 本项**不改签名形态**（`judge(raw, expected)`），只改返回类型 → 仍算 MAJOR，需你确认。

> ⚠️ 若你选 bool，则需同步改：PLAYBOOK §5、两个真源的 adapter 层各加转换、
> `settle.py` 风格的调用方语义丢失。**成本明显更高，不建议。**

## B2 —— `pick` 注入点缺失（**本批次最严重**）

### 实测：内核骨架 vs 真源，差距远不止"三个参数"

**真源 `bb-prep/src/practice.py:81-167` 的完整形态**：

```python
def pick_items(n_review, n_new, rng, ref=None, exam_first=True,
               exclude=None, weighted=True) -> tuple[list[dict], list[dict]]:
```

内部逻辑（实测）：

| 环节 | 真源实现 | 内核骨架 |
|---|---|---|
| 到期池 | `B.is_due(i, t)` | 内联 `_is_due`（重复实现，见 B6） |
| 真题优先 | `if exam_first:` 参数化分支 | **硬编码**进排序键 |
| 九域权重 | `domain_deficit(history_domain_counts())` | `_domain_deficit(_history_counts())` ← **两个函数都恒返回 `{}`** |
| 新题选取 | **贪心 + 温和上限**：`cap = max(1, ceil(w/tot*n_sheet)+1)`，逐题减欠配量 | **无此逻辑**，只有 `fresh[:new_n]` 切片 |
| 近期去重 | 由 `exclude` 参数承载（调用方传） | `getattr(self, "_recent", set())` ← **恒为空集** |
| 回退补位 | 打乱后再按真题优先重排 | `rest.pop()` 随机弹（**丢真题优先**） |

### 关键发现（超出审计报告）

审计说"丢三个注入点"，**实测更严重**：内核漏掉了**整个"贪心取新题 + 温和上限"算法**。

真源注释里明写这是踩过坑的（`practice.py:114-121`）：

> "再加一道**温和上限**，防止某个长期欠练的域（如 D2-过程管理）在一张卷里独占"
> "10 题的卷子按硬配额根本放不下 D2/D9……只有『滚动欠配』才可能把它们补上"

以及 `practice.py:109-112` 的二次 shuffle 教训：

> "此处绝不能再 shuffle(new)——上面已按『真题优先』排好序，再打乱会把真题优先彻底冲掉"

**内核骨架里这两个教训全丢了。** `while ... rest.pop()` 那段正是被明确禁止的"打乱后随机弹"。

### 判断

这不是"三个参数忘了传"，而是**内核骨架比真源少了一整个算法模块**。

### 建议：**分两步走，不要一次吃下**

**第一步（B2 裁决即刻）—— 接口定形，逻辑先不追平**：

建议把 `pick` 契约改为**显式注入**，签名如下（与真源对齐）：

```python
def pick(self, review_n, new_n, items, rng, ref,
         exam_first=True, exclude=None, weighted=True,
         recent=None, history_counts=None, domain_weights=None, ladder=None):
```

三处 `getattr` / 恒定 `{}` **全部改为显式形参**，默认值保持"未注入=不过滤"，
使行为可预测、可测试。

**第二步（P1-A 实现时）—— 补算法**：

- 补「贪心 + 温和上限」新题选取（按真源 `practice.py:122-155` 移植）
- 修回退补位：`rest.pop()` → 打乱后按 `(not is_exam, -deficit, rng.random())` 重排
- 建议**同一提交内**完成，否则 P1-A 交给 bb-prep 的卷子会退化

### ⚠️ 关于「静默丢掉近期去重」的实际风险

审计说"P1-A 会静默丢掉 bb-prep 刚修的近期去重"。**实测下这个表述需要修正**：

bb-prep 真源 `pick_items` **本身也没有 `recent` 形参**——去重靠调用方传 `exclude`。
所以内核用 `_recent`（空集）**不会丢** bb-prep 现有行为（因为 bb-prep 本来就用 `exclude`），
但会让**内核自称支持的 `recent` 能力是个摆设**。

**结论**：风险等级从 🔴 降为 🟠 —— 不是"会退化"，是"接口承诺了但没实现"。

## B3 —— ADR-0002 是否补「固定 rng 种子」

### 实测

| 位置 | 实测 |
|---|---|
| `bb-prep/src/practice.py:366` | `p.add_argument("--seed", type=int, default=None, help="测试用随机种子")` |
| `bb-prep/src/practice.py:386` | `rng = random.Random(a.seed)` |
| `bb-prep pick_items` 内部 | `rng.random()`（排序键）、`rng.shuffle(due)`、`rng.shuffle(rest)` |
| `ADR-0002` | 门槛写"固定 items + 固定 `today` → 逐字节比对"，**未提 rng** |

### 判断

**审计成立且成立得很硬**。`--seed` 参数**已经在真源里存在**（而且 help 文本就写着"测试用"），
等于说 bb-prep 早就为可复现验收准备好了钩子，而 ADR-0002 的判据没接上。

不固定的后果：`rng` 未播种时 `Random(None)` 用系统熵 → 同输入两次跑出不同卷面 →
**逐字节比对必然失败，与代码改动无关** → 判据变成噪音源。

### 建议：**必须固定，列为验收第 0 步**

ADR-0002 通过门槛补一行：

```
0. 固定 rng = random.Random(<FIXED_SEED>) 且 --seed <FIXED_SEED>；
   未固定随机源时，逐字节比对不成立（判据作废）。
```

并建议：**FIXED_SEED 写入 ADR 正文**（如 `20261010`），不要留给执行者临场选，
否则不同人跑出不同基线。

## B4 —— `new` 是否进 `model.STATES`

### 实测

| 位置 | 实测 |
|---|---|
| `bb-prep/src/bbcore.py:172` | `fm.setdefault("state", "new")` ← **建卡即 `new`** |
| `bb-prep practice.py:90-91` | `due = [i ... if i.get("state") != "new" and is_due]` / `new = [... == "new"]` |
| `vocab-app/src/review.py:118` | `fm.setdefault("state", "new")` |
| `LESSON-OS learn_engine/model.py:18` | `STATES = ("learning", "review", "mastered", "lapsed")` ← **无 `new`** |
| `LESSON-OS learn_engine/picker.py:39-40` | `i.get("state", "new") != "new"` ← **内核自己按 `new` 分池** |

### 判断

内核**自相矛盾**：`picker` 按 `new` 分池，`model.STATES` 里却没有 `new`。

但"把 `new` 加进 `STATES` 元组"这个解法**不对**。原因是语义层级不同：

- `new` **不是** SRS 状态机的一个状态 —— 它是**"尚未进入状态机"**的标记。
  状态机的转移只在 `learning → review → mastered / lapsed` 之间发生
  （见 `scheduler.next_schedule`，输入是 `correct: bool`，`new` 卡根本不会被判分）。
- 两个真源都是 `setdefault("state", "new")` —— `new` 是**默认值/未初始化哨兵**，
  不是流转出来的状态。

**误把 `new` 塞进 `STATES` 会让 `next_schedule` 的合法输入域变模糊** ——
未来有人传 `state="new"` 进状态机就会得到无意义结果。

### 建议：**用两个具名常量表达二分，而不是扩充 `STATES`**

```python
STATES = ("learning", "review", "mastered", "lapsed")   # 状态机合法态（不变）
POOL_NEW = "new"        # 新增：未建卡哨兵（pool 分流用，不入状态机）
POOL_REVIEW = "due"     # 可选：概念命名，便于 picker 表达
```

并加一行 docstring 说清：**`new` 是 pool 分流哨兵，不是 SRS 状态**。

这样：
- `picker` 引用 `POOL_NEW` 而非硬编码 `"new"` 字面量 → 单一真源
- `STATES` 语义保持纯净（只有能进状态机的态）
- PLAYBOOK §3 的 schema 表补一行说明 `new` 的性质

> 若你坚持"简化"（直接把 `new` 加进 `STATES`），代价是状态机语义被稀释，
> 后续接 FSRS 时会更混乱。**建议前者。**
