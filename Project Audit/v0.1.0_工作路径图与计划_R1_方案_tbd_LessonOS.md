### 内核内部模块（learn_engine/，已落骨架）
```
learn_engine/
├── __init__.py     __version__="0.1.0" + 公开 API
├── model.py        Item + DEFAULT_LADDER(注入) + MASTER_STAGE
├── scheduler.py    is_due + next_schedule(状态机) + apply_result
├── vault.py        parse_front / write_front / as_date (stdlib regex)
├── grader.py       Grader 接口 + ExactMatchGrader(vocab 风格 adapter)
└── picker.py       Picker 接口 + WeightedPicker(bb 风格 adapter)
```

### 数据流（以一次练习为例）
1. `vault.parse_front` 读条目 → `Item`
2. `picker.pick` 按「到期优先 + 九域权重 + 近期去重」出卷（adapter 决定抽题规则）
3. 用户作答 → `grader.judge` 确定性判分（adapter 决定答案形态）
4. `scheduler.apply_result` 更新 stage/state/due（LADDER 注入）
5. `vault.write_front` 回写（adapter 注入具体 writer）

## 三、内核 API 契约（终版）

| 符号 | 签名 | 说明 |
|---|---|---|
| `is_due(it, ref)` | `-> bool` | 到期判定（同源，同形） |
| `next_schedule(old, correct, ladder=None)` | `-> (stage, state, gap)` | 状态机（ladder 注入） |
| `apply_result(item, correct, ladder=None, *, write_front=None, today=None)` | `-> dict` | 更新 stage/state/due |
| `parse_front(text)` / `write_front(path, updates)` / `as_date(v)` | — | frontmatter IO（stdlib） |
| `Grader.judge(raw, expected)` | `-> bool` | 判定策略接口（adapter） |
| `Picker.pick(...)` | `-> (review, new)` | 出卷策略接口（adapter） |

**铁律**：判分确定性、模型不参与；LADDER 注入不硬编码；改动前先读调用者；小步零中断。

## 四、版本闸门策略
- 内核头 `__version__ = "x.y.z"`（语义版本）。
- 各项目 `git submodule` 钉 commit，或 `vendor/` 放 pinned 副本。
- 改核心 → 只 bump 号；其他项目**不主动升级不受影响**。
- 交付时整文件拷贝 `learn_engine/`（纯 stdlib，脱离代码库）。
