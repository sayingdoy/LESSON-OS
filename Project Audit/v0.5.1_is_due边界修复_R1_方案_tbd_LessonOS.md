## 一、问题（全部实测）

`scheduler.is_due` 只兜住 `None` 与 `str` 两条输入路，其余值原样进入
`d <= ref`。非 str/非 None/非 date 的值（int / bool）**直接崩溃**：

| 输入 | 现状（0.5.0 实跑） | 期望 |
|---|---|---|
| `{'due': 0}` | **TypeError**（`'<' not supported between instances of 'int' and 'datetime.date'`） | `True`（到期） |
| `{'due': False}` | **TypeError** | `True` |
| `{'due': 1}` | TypeError（同类） | `True` |
| `{'due': None}` | `True` | `True` |
| `{'due': ''}` / `{'due': 'garbage'}` | `True` | `True` |
| `{'due': '2026-01-01'}`（过去） | `False` | `False` |
| `{'due': date(2026,1,1)}` | `False` | `False` |

**触发条件**：frontmatter `due: 0` / `due: false` / `due: 1` —— bb-prep 与
vocab-app 的 `parse_front` 均有**数值/布尔强转**（`due: 0` → int 0），
脏数据或手改文件可达。

**暴露面实测**：两消费方**均保留本地 `is_due`**（bb-prep `bbcore.py:215`；
vocab-app `review.py`，注释明记此边界差异），对内核 `is_due` **零调用**
（`LE\.is_due` / `learn_engine.*is_due` 模式 grep 无命中）。
→ 今天不咬人；但内核 `is_due` 的 docstring advertising「与 bb-prep/vocab-app
**同名同形**」，下一个按文档委托的消费方（AI-Kongzi Sprint 2B 候选）会踩到。

## 二、根因

`is_due` 隐含假设「非 None 非 str 的输入皆是 date 对象」。而两消费方的真源
语义是**经 `as_date` 归一**（不可解析 → None → 到期）。内核自己的
`vault.as_date` 与两消费方**全边界等价**（vocab-app P2 基线 29 例 0 差异
已证）—— 缺的只是 `is_due` 把同一归一补上。

## 三、方案（diff 级，唯一改动点）

`scheduler.py::is_due` 增加一条分支（3 行）：

```python
    if isinstance(d, str):
        try:
            d = dt.date.fromisoformat(d[:10])
        except ValueError:
            return True
    elif not isinstance(d, dt.date):
        return True   # 新增：非 str/date（int/bool 等）按「不可解析」→ 到期。
                      # 与两消费方本地语义逐案一致（均返回 True），
                      # 且与同一函数的 str-坏值路径同果。
    return d <= ref
```

- 不引 `vault`（避免 scheduler → vault 耦合，保持内核模块单向依赖）
- 不改签名、不改既有路径行为（None / str / date 三分支原样）

## 四、影响面

- **回归风险 ≈ 0**：内核 `is_due` 零调用方（实测）；行为只在「当前抛
  TypeError 的输入」上变化（崩 → `True`）
- **消费方零联动**：两处本地 `is_due` 保持不动（本 PATCH 不强制重新委托；
  重新委托是各消费方自己的 P2+ 决策）
- **golden-set**：新增 `is_due` 边界断言 **10 例**（None / "" / 0 / False /
  1 / "garbage" / 过去串 / 未来串 / 过去 date / 未来 date）→ 47 + 10 项
- **bump**：`0.5.0 → 0.5.1`（PATCH：仅修崩溃路径）。**三处同步**：
  `learn_engine/__init__.py` 的 `__version__` + `PLAYBOOK.md` frontmatter
  `version` + `CHANGELOG.md` 补一条
- **不在本方案范围**（明示）：`picker._is_due` 有同形状问题，但它是内核内部
  函数、将被技术债 **B6**（四份日期解析收敛）一并处理，不扩大本 PATCH 爆炸面
- 落地后更新 ADR-0009「后续」节（移除该候选）
